Manual Técnico - SuperResolution NDI Streaming

Este manual describe la implementación actual del streamer NDI en Python. El foco principal de la arquitectura es mantener sincronía A/V estable en sesiones largas, reducir capas opacas y dejar una base clara para extender features como overlays de viewport enviados desde Unity.

Navegación
  • Versión EN
  • Decisión: sender directo con libndi
  • Decisión: timeline único con PyAV

1. Resumen ejecutivo

  • Entrada principal: stream_video.py.
  • Decode A/V unificado: media_reader.py con PyAV.
  • Sender NDI: ndi_native.py con libndi directo.
  • Procesado de frame y overlays: numpy.
  • Backchannel Unity: metadata NDI recibida y dibujada opcionalmente sobre el vídeo saliente.

2. Arquitectura actual

CLI -> LoopingMediaReader (PyAV)
    -> eventos de media ordenados por tiempo (video/audio)
    -> reloj único de reproducción en stream_video.py
    -> NativeNdiSender (libndi)
    -> salida NDI principal
    -> salida NDI secundaria opcional (--dual)
    -> overlay opcional con metadata de Unity

La decisión clave es que audio y vídeo salen del mismo timeline de media. El sistema ya no reconstruye audio por ventanas calculadas a partir del frame index de vídeo.

5. Decisiones de diseño activas

  • Una sola autoridad de timing: el reloj de reproducción vive en stream_video.py.
  • Timeline único de media: PyAV entrega eventos A/V desde el mismo contenedor.
  • Sender directo: se evita el wrapper de alto nivel para reducir buffering opaco.
  • Extensión por metadata: el overlay de viewport no redefine el pipeline base, solo lo enriquece.

6. Flujo de ejecución

  1. Se parsean argumentos CLI.
  2. LoopingMediaReader abre el media y detecta streams de vídeo y audio.
  3. Se configuran sender principal y sender secundario opcional.
  4. El runtime recibe eventos de vídeo o audio ya ordenados por tiempo de media.
  5. El scheduler espera al deadline correspondiente y envía el frame o bloque de audio.
  6. Si hay metadata reciente de Unity, se dibuja sobre el frame de vídeo antes de enviarlo.
  7. Al llegar al final del clip, el reader reabre el media y continúa con offset temporal acumulado.

7. Operación

python3 -m pip install -r requirements.txt
python3 stream_video.py
python3 stream_video.py Videos/big_buck_bunny.mp4 --dual
python3 stream_video.py Videos/big_buck_bunny.mp4 --rx-metadata-verbose

8. QA recomendado

Matriz ya validada a fecha 2026-06-18:

  • NDI Monitor
  • Unity Editor
  • Unity AVP Simulator
  • Build en Apple Vision Pro

QA operativo recomendado a partir de aquí:

  1. Validar primero en NDI Monitor.
  2. Repetir después en Unity.
  3. Probar sesiones largas con señales representativas de producción.
  4. Comparar 24/23.976 fps y 60/59.94 fps.
  5. Comprobar fuentes con audio, sin audio y cambios de señal si aplican.
